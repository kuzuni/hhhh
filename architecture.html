02제작 파이프라인 — 멀티에이전트 스튜디오

AI 에이전트들이 스튜디오처럼 분업한다: 병렬 빌더가 만들고, 각자 헤드리스 스크린샷으로 자기 그림을 직접 보며 고치고, 3인 심사 패널이 채점하고, 떨어지면 수정 라운드가 돈다. 사람(관객)은 그동안 실시간 배포로 과정을 지켜본다.

📜
스펙 — 아트 디렉션 계약서

공통 스펙(미소년 얼굴 공식·비율·선·셰이딩·애니 원칙·몽타주 규격) + 캐릭터별 스펙(컨셉·팔레트·기법 정의·애니 목록). 빌더와 심사위원이 같은 문서를 본다.

🎨
빌더 병렬 — 트랙 3개 동시 가동

페이지당 빌더 1명. 단일 HTML을 작성한 뒤 자가검증 루프 최소 4회: bash tools/shot2.sh page.html?montage out.png → 헤드리스 Edge 렌더 → 에이전트가 PNG를 눈으로 보고 결함 목록 → 수정 → 재촬영. 트랙별 워크플로우가 서로 독립적으로 병렬 진행.

용사 트랙 ×2아스렐·루시엘
치비 트랙 ×2리코 + 아바타 시스템
몬스터 트랙 ×4투기·펌킨조 + 음식조각 죽음
⚖️
심사 패널 ×3 — 렌즈 분리

① 미소년 얼굴·아트 디렉션 ② 애니메이션·모션 ③ 테크니컬 아트·기법 시연. 각자 몽타주 PNG를 보고 face / art / motion / technique / polish 5개 축 + 종합점수(0~10)와 위치 특정 이슈를 제출.

✅
합격 게이트

전원 8.0 이상 + critical 이슈 0개. 미달이면 ↓

↺ 최대 3라운드
🔧
수정 에이전트

심사 이슈(JSON)를 심각도 순으로 반영 → 재촬영 → 스스로 확인 → 재심사로 복귀.

🚀
배포 — 그때그때

워처가 2분마다 변경 감지 → git commit + push → GitHub Pages 자동 반영. 심사 점수가 낮아도 일단 라이브에 올라가고, 라운드가 돌수록 퀄리티가 올라간다. 최종적으로 오케스트레이터가 직접 검수 후 마무리 커밋.

03런타임 리깅 — 세 가지 설계

셋 다 Canvas 2D 위에서 돌지만, "그림이 어떻게 움직이는가"의 답이 근본적으로 다르다. 그 차이 자체가 각 페이지의 주제다.

절차적 스켈레톤 + IK

hero-blade.html · 아스렐
  • 본 트리 pelvis→spine→chest→목/사지, 매 프레임 애니 커브 → 트랜스폼 계산
  • 2본 해석 IK — 보행 발 접지(미끄러짐 0), 베기 양손 그립
  • 팔다리는 관절에서 부드럽게 휘는 테이퍼 곡선으로 매 프레임 드로잉
  • 검격 리본 트레일 + 포즈 잔상도 본 데이터에서 파생
  • pose(anim,t) 순수함수 → 실시간·몽타주 공용

컷아웃 리깅 (퍼펫)

hero-puppet.html · 루시엘
  • 부품 ~20개를 초기화 때 1회만 오프스크린 캔버스에 굽는다
  • 매 프레임은 씬그래프 리지드 변환만 — pivot·rot·z순서 (Spine 방식)
  • 키프레임 트랙 + 큐빅 이징, 애니 간 크로스페이드
  • 손·검끝 드래그 → 실시간 IK, 놓으면 스프링 복귀
  • 「부품 분해」 뷰 — 조각들이 이름표 달고 날아가는 컷아웃 증명샷

메시 디포메이션 (Live2D식)

hero-live.html · 카이렌
  • 레이어 15~20장(홍채·눈꺼풀·앞머리 가닥까지 분리)을 1회 텍스처링
  • 레이어마다 삼각 격자 메시 + 정점 가중치 — 파라미터 합산으로 정점 이동
  • 파라미터: yaw·pitch·roll / 시선 / blink / breath / hairSway…
  • Canvas2D 텍스처 삼각형(clip+setTransform+drawImage), 실금 방지 팽창
  • 레이어 깊이 시차로 3D 착시 + 머리카락 스프링 물리 + 마우스 추적

04공통 설계 원칙

단일 파일 · 외부 리소스 0폰트·이미지·CDN 없이 모든 그래픽을 코드로 그린다. 파일 하나 = 배포 단위 하나 = URL 하나.
Canvas 2D 전용WebGL 금지 — --disable-gpu 헤드리스에서도 100% 동일 렌더 → 스크린샷 검증 파이프라인이 성립한다.
결정론 몽타주 모드?montage가 붙으면 rAF 대신 고정 시각 t로 동기 렌더. Row A 주모션 6칸 / Row B 액션 6칸 / Row C 뷰티·얼굴 클로즈업·리깅 오버레이·기법 특화 컷. 심사가 항상 같은 그림을 본다.
에러 가시화window.onerror를 화면 위 빨간 텍스트로 — 헤드리스 스크린샷에서도 버그가 "보인다".
포즈 = 순수함수시간 → 포즈 계산을 부작용 없이 분리. 실시간 루프와 몽타주가 같은 함수를 공유해 검증 대상과 실물이 어긋나지 않는다.
애니메이션 문법선형 보간 금지, 예비동작→급가속→임팩트 홀드→회수, 머리카락·망토는 지연 추종(오버랩), 발 미끄러짐 금지.
아바타 = 스킨, 리그 = 하나몸·뼈·애니메이션은 공유하고 의상·무기 세트만 교체. 리코(해적↔마법사)·투기(기본↔불속성)·펌킨조(기본↔악마)가 전부 이 구조 — 유니티 Sprite Library로 그대로 이식되는 설계.
무해한 죽음 연출몬스터는 쓰러지면 뿅! 하고 음식 조각(햄·스테이크 / 호박 웨지)으로 치환. 조각에 신체 요소 금지, 피 금지 — 잔인함 0%, 맛있음 100%가 심사 기준.
